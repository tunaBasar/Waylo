# Waylo mobile (Expo)

Expo SDK 58, React Native, TypeScript, expo-router. Framework rationale: `ADR-mobile-framework.md`.

## Run
```bash
cd mobile
npm install
npm start            # then press a (Android emulator), or scan the QR with Expo Go
```
Backend must be reachable through the API gateway (`./boot.sh start`, gateway on :8080).

## API URL
`src/config.ts` reads `EXPO_PUBLIC_API_URL`. Defaults:
- Android emulator: `http://10.0.2.2:8080`
- iOS simulator / web: `http://localhost:8080`
- Physical device: use your computer's LAN IP, e.g.
  `EXPO_PUBLIC_API_URL=http://192.168.1.20:8080 npm start`

Web preview (`npm run web`) is a browser, so the gateway CORS allow-list must include the dev origin
(the gateway default `WAYLO_CORS_ORIGINS` now includes `http://localhost:3000` and `http://localhost:8081`). Native builds are not affected by CORS.

## Layout
`src/api` (typed client, refresh on 401, SecureStore tokens), `src/features/*` (auth, hotels, flights, cars,
bus, cart, orders, profile), `src/app` (expo-router screens), `src/components` (UI primitives).

## Notes
- Payment is the sandbox flow (TEST_OK / TEST_DECLINE). Success is shown only when the backend order status is CONFIRMED.
- Bus is read-only and hidden when `/api/bus-sales-status` says disabled.
- Cart persists in AsyncStorage (`waylo.cart.v1`, cart only; tokens stay in SecureStore and are never written to AsyncStorage). Prices/stock are always fetched online and re-priced by the server at checkout.
- Dates use a real picker (`DateField`: system picker on native, browser date input on web). Dates are local calendar values, never via toISOString.
- Hotel search has rooms, adults and children with ages like the web. Car search has separate pickup and return branches (different = one-way).
- Reviews (`/reviews`, hotel detail rating + list), online check-in for FLIGHT items on the order screen (window per CHECKIN-CONTRACT, voucher QR is the boarding credential), profile edit, change password (keeps the session with the fresh token pair), settings (logout, delete account), notifications (`GET /api/notifications/me`).
- Web preview has no SecureStore backend: the session is not kept across a browser reload (by design, no tokens in localStorage).
- Push (`src/features/push/registration.ts`): after login the app asks notification permission, gets the Expo push token and `POST /api/me/devices`; logout calls `DELETE /api/me/devices/{token}` before clearing the session. **An EAS projectId is required** (`expo.extra.eas.projectId` in app.json, created with `eas init`). Until it is set, registration is skipped with a console warning (user decision pending). Backend sending is off unless `EXPO_PUSH_ENABLED=true` on notification-service. Only works on physical devices.
- Jest: `jest.setup.js` mocks AsyncStorage globally.

## Release (EAS)
`eas.json` has three profiles. `EXPO_PUBLIC_API_URL` is set per profile:
- `development`: internal debug APK / iOS simulator build, `http://10.0.2.2:8080` (emulator -> host gateway).
- `preview`: internal APK, `https://staging-api.waylo.example.com` (placeholder).
- `production`: store build, `https://api.waylo.example.com` (placeholder), `autoIncrement` build numbers.

No EAS account is linked yet (`eas init` not run, no `projectId`), so nothing has been built on EAS.

**User decisions (temporary, confirm before the first store upload):**
- Bundle id / Android package: `com.waylo.app`.
- Universal/App link host: `waylo.example.com` (placeholder in `app.json` `ios.associatedDomains` and the Android `intentFilters`).
  The real domain must serve `/.well-known/apple-app-site-association` and `/.well-known/assetlinks.json`.
- API URLs for preview/production above are placeholders.
- Icons: the repo has no logo file (the web shows the text "Waylo" with primary `#004ac6`), so a simple text icon
  (white "W" on `#004ac6`) is generated by `node scripts/generate-icons.mjs` (uses `sharp` from `frontend/node_modules`).
  Replace `assets/images/waylo-*.png` when a real logo exists.

Version: `expo.version` 1.0.0, iOS `buildNumber` 1, Android `versionCode` 1.
Permissions: Android requests only `POST_NOTIFICATIONS` (push); `CAMERA`, `RECORD_AUDIO`, `SYSTEM_ALERT_WINDOW` are blocked.
No camera/location/photo usage in the app, so no iOS usage descriptions are needed.

## Deep links
Scheme `waylo` plus https placeholders on `waylo.example.com`:
- `waylo://order/<id>`, `https://<host>/order/<id>`: order detail. Opened signed out, the link is remembered and
  opened after login (`src/features/deeplinks.ts`).
- `waylo://verify?token=...`, `/verify?token=...`: email verification (`GET /api/auth/verify`), works signed in or out.
- `waylo://reset-password?token=...`, `/reset-password?token=...`: new password form (`POST /api/auth/reset-password`).

The backend emails currently link to the web frontend; pointing them at the app host is a backend decision.

## Offline
`@react-native-community/netinfo` (plus window online/offline events on web) drives a global banner.
Offline, "Siparisi olustur", the test payment buttons and cancellation confirm are disabled.
The orders list is cached read-only (`waylo.orders.v1`, cleared on logout) and shown offline with a "Cevrimdisi" note.
Search results, quotes and prices are never cached, so nothing bookable is shown offline.

## Accessibility / text
Every pressable has `accessibilityRole` and `accessibilityLabel` (`__tests__/a11y-screens.test.tsx` walks the
rendered tree of each main screen). Font scaling is left on (no `allowFontScaling={false}`). Error banners use
`accessibilityRole="alert"`, the loading spinner has a label. Turkish strings stay ASCII-transliterated (e.g.
"Siparis", "Giris") like the web, which uses ASCII almost everywhere (only a few strings like "Aranıyor" use ı/ş).
